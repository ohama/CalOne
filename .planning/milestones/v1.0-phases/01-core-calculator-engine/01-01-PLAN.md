<task type="auto">
  <name>Task 1: Create calculator state object and basic arithmetic</name>
  <files>js/calculator.js</files>
  <action>
Create `js/calculator.js` with calculator state object and basic arithmetic operations.

**State object structure (from RESEARCH Pattern 1):**
```javascript
const calculator = {
  displayValue: '0',
  firstOperand: null,
  waitingForSecondOperand: false,
  operator: null,
};
```

**Implement these functions:**

1. `inputDigit(digit)` - Handle number input (0-9)
   - If waitingForSecondOperand, start fresh with digit
   - Otherwise, concatenate to displayValue (replace '0' if current value is '0')

2. `inputDecimal(dot)` - Handle decimal point input
   - If waitingForSecondOperand, start with '0.'
   - Otherwise, only append if displayValue doesn't already include('.')
   - This prevents multiple decimal points (CALC-04)

3. `handleOperator(nextOperator)` - Handle operator selection (+, -, ×, ÷, =)
   - If operator exists and waitingForSecondOperand, replace operator (allows changing mind)
   - If firstOperand is null, store current value as firstOperand
   - If operator exists and !waitingForSecondOperand, calculate result and chain
   - Set waitingForSecondOperand = true

4. `performCalculation()` - Execute arithmetic operation
   - Get prev (firstOperand) and current (displayValue) as numbers
   - **GUARD CLAUSE:** If operator is '÷' and current is 0, return 'Error' (CALC-05)
   - Use switch statement for +, -, ×, ÷ (NEVER use eval())
   - **PRECISION FIX:** Return `parseFloat(result.toFixed(10))` to fix floating-point errors (CALC-06)
   - This ensures 0.1 + 0.2 = 0.3, not 0.30000000000000004

5. `resetCalculator()` - AC (All Clear) function
   - Reset all state: displayValue = '0', firstOperand = null, operator = null, waitingForSecondOperand = false

**Why these patterns:**
- State object pattern prevents broken operation chaining (RESEARCH Pitfall 1)
- includes() check prevents multiple decimals (RESEARCH Pitfall 2)
- toFixed(10) + parseFloat() fixes floating-point display (RESEARCH Pitfall 3)
- Division by zero guard prevents Infinity display (RESEARCH Pitfall 4)
  </action>

```javascript

// displayValue should be '8'

```

<task type="auto">
  <name>Task 2: Add percent, sign toggle, and display formatting</name>
  <files>js/calculator.js</files>
  <action>
Add remaining calculator functions to `js/calculator.js`.

**Implement these functions:**

1. `toggleSign()` - Flip sign of current number (CALC-03)
   - Parse displayValue to number
   - Multiply by -1
   - Convert back to string and set as displayValue
   - Simple and works for both positive and negative

2. `handlePercent()` - Calculate percentage (CALC-02)
   - If firstOperand exists and operator exists:
     - Contextual percent: `percentValue = (firstOperand * current) / 100`
     - Example: "50 + 10%" means 50 + (50 × 0.1) = 55
   - Otherwise:
     - Simple conversion: `displayValue = current / 100`
     - Example: "25%" → 0.25
   - This matches iOS calculator behavior (RESEARCH Pattern 8)

3. `formatForDisplay(value, maxDigits = 10)` - Handle display overflow (INPT-05)
   - If value is 'Error', return as-is
   - Convert to string and count digits (excluding '-' and '.')
   - If exceeds maxDigits, return `Number(value).toExponential(2)`
   - Otherwise return string unchanged
   - This prevents layout breaking with 15+ digit numbers (RESEARCH Pitfall 5)

**Why these patterns:**
- Percent uses contextual calculation matching user expectations (RESEARCH Pattern 8)
- Sign toggle is simple multiplication by -1 (RESEARCH Pattern 7)
- formatForDisplay uses scientific notation for overflow (RESEARCH Pattern 6)
  </action>
  <verify>
Browser console tests:
