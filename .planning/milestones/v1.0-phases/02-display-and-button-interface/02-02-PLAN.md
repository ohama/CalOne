
**Implementation logic (reference RESEARCH.md "Backspace Implementation"):**
1. Destructure `displayValue` and `waitingForSecondOperand` from calculator state
2. **If displayValue is 'Error':** Reset to '0' and return
3. **If waitingForSecondOperand is true:** Reset to '0', set waitingForSecondOperand to false, return
4. **If single digit (length === 1):** Reset to '0' and return
5. **If single digit with negative sign (length === 2 and starts with '-'):** Reset to '0' and return
6. **Otherwise:** Remove last character using `displayValue.slice(0, -1)`

**Edge cases covered:**
- Error state: "Error" → backspace → "0" (not "Erro")
- After equals: waitingForSecondOperand is true, backspace resets to "0"
- Single digit: "5" → backspace → "0" (not empty string)
- Negative single digit: "-3" → backspace → "0" (not "-")
- Normal case: "123" → backspace → "12"

**Why these edge cases matter:**
- RESEARCH Pitfall 6 documents bugs when backspace isn't validated against state
- Empty string breaks display and causes parseFloat(NaN) errors
- "Erro" doesn't match 'Error' checks elsewhere in code
- waitingForSecondOperand flag prevents editing first operand after operator press

Reference RESEARCH.md "Backspace Implementation" section for complete code.
